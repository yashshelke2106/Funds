# DECISIONS

Every judgement call, the alternatives considered, and why. Newest at the bottom.

| ID | Date | Decision | Alternatives | Why |
|---|---|---|---|---|
| D-001 | 2026-09-25 | Source file layouts are taken from files actually downloaded on 2026-09-25 (AMFI `NAVAll.txt`, AMFI `DownloadNAVHistoryReport_Po.aspx?frmdt=02-Sep-2024`, mfapi `/mf/118825`). Parsers check the header line and stop with `FormatChangedError` if it differs. | Parse leniently by column position. | NAVAll now has **8 columns** (`Plan`, `Option` were added); the history report has a **different column order** from NAVAll. Parsing by position without checking would silently misread both. |
| D-002 | 2026-09-25 | The universe is **derived** from AMFI category headers (`Equity Scheme(s) - Large Cap Fund`), not a hand-typed list. Growth option only, with Direct/Regular pairs matched on (AMC, scheme name). | Hand-picked list of well-known funds. | A hand-picked list adds selection bias and can't be reproduced. AMFI spells the category two ways (`Equity Scheme` / `Equity Schemes`); both are normalised. |
| D-003 | 2026-09-25 | Holdings window = **Sep-2024 to Aug-2026** (24 complete months). | Rolling "last 24 months" from run date. | A fixed window makes results reproducible. Aug-2026 portfolios are due by 10-Sep-2026 (SEBI monthly disclosure deadline), so they are available. |
| D-004 | 2026-09-25 | NAV history is fetched from **Sep-2023** (12 months before the holdings window). | Fetch NAVs only for the holdings window. | Rolling 12-month tracking error then exists for every month of the holdings window, not just the last 12. Funds lacking this lookback are flagged (`covers_rolling_lookback`), not dropped. |
| D-005 | 2026-09-25 | **Eligibility** = Direct and Regular NAV history covers the whole holdings window **and** the AMFI ISIN matches the mfapi ISIN for both plans. Funds launched after the window start are excluded and listed. | Include young funds on a partial window. | Active share and TE averaged over different windows are not comparable. The exclusion is listed, not hidden. |
| D-006 | 2026-09-25 | NAV gaps are counted in **weekdays** (Mon–Fri). A gap of more than 5 is a *flag*, not a failure. Non-positive NAV and duplicate dates are *failures*. | Use the NSE holiday calendar. | No holiday calendar is in scope yet. Weekday counting over-flags around long holiday runs, so gaps are reviewed by hand rather than causing automatic failure. Revisit if flags turn out to be noisy. |
| D-007 | 2026-09-25 | Survivorship check compares Large Cap Growth scheme codes in the AMFI snapshot of **02-Sep-2024** against the current NAVAll. | Rely on AMC press releases. | This is mechanical and repeatable. The match is **by scheme code only**: the history report's `NAV Name` embeds plan and option text while NAVAll gives the bare name, so a name comparison would mark every scheme as renamed. Both names are output for a human to review. Limitation: a scheme launched *and* closed inside the window would be missed. |
| D-008 | 2026-09-25 | Unit-test fixtures are **verbatim excerpts** of the real files (rows copied, never edited). Only rule and metric unit tests (quality checks, P4 metrics) use small hand-built inputs; these exercise the logic, never feed an analysis, and live only under `tests/`. | Invented sample rows. | Complies with the no-synthetic-data rule. Some failure cases (e.g. a negative NAV) can't be taken from real data, and hand-calculated metric examples are required by the brief (P4). |
| D-009 | 2026-09-25 | **Look-ahead rule (applies from P2):** month M's portfolio counts as *known* only from the 11th day of month M+1 (SEBI 10-day disclosure deadline). Any analysis that pairs holdings with returns uses returns from after that date. | Treat month-end holdings as known at month end. | Using them at month end is look-ahead bias. |
| D-010 | 2026-09-25 | Candidate benchmark-weight proxies: Axis, Bandhan and HDFC Nifty 100 Index Funds (the only exact "Nifty 100 Index Fund" names in AMFI today). **Choice deferred to P2**: pick the one with the lowest tracking error to its own benchmark over the window. | Pick one now. | Choosing before seeing the data would be arbitrary. All three NAV series are fetched so the choice can be tested. |
| D-011 | 2026-09-25 | Portfolio disclosures are ingested for **Sep-2025 to Aug-2026 (12 months)**. NAV-based metrics (TE, rolling returns, IR) keep the full Sep-2024 to Aug-2026 window with a 12-month lookback. *Amends D-003.* | 24 months of holdings (~744 manual files). | Halves the manual downloads to about 372 files. Active share is fairly stable month to month, so the classification loses little. Cost: the turnover proxy and active-share trend cover only 12 months, and the memo will say so. |
| D-012 | 2026-09-25 | Funds that pass eligibility but lack the 12-month pre-window NAV lookback get `report_group = partial_history` and are **reported separately**, not ranked with the main set. On the P1 run this is only Bajaj Finserv Large Cap (first NAV 23-Aug-2024). | Include in the main set; exclude entirely. | Its rolling TE and IR exist only from Aug-2025, and its first portfolios fall in the launch-money investment period, so it isn't comparable with the other 30. Reporting it separately keeps the evidence without distorting the ranking. |
| D-013 | 2026-09-25 | Benchmark returns = **Nifty 100 TRI** from niftyindices.com, supplied by the user (Sep-2023 to Aug-2026). The index-fund-NAV fallback in D-010 is kept only for benchmark *weights*. | Use an index fund's NAV for returns. | An index fund's NAV understates the benchmark by its TER and tracking error, which would bias excess returns and fee drag in the active funds' favour. |
| P1-ACCEPT | 2026-09-25 | Phase 1 accepted, based on the user's run: universe 37 (34 active, 3 index); 74/74 NAV codes fetched; 51,997 NAV rows; eligible active funds 31/34 (Samco, PPFAS and JioBlackRock excluded as too young); 0 NAV quality issues; 744 portfolio items at 24 months (becomes 372 under D-011); 32 tests passed. | — | Record of the acceptance checks. |
| D-014 | 2026-09-25 | **The TRI's trading calendar is the master calendar** for every daily-return calculation. NAVs on non-TRI days (31-Mar year-end NAVs, some funds' weekend month-end NAVs) are dropped. A TRI day with no NAV is removed from both series, so the next return spans the gap in both. **No forward fill.** | Use each fund's own NAV calendar; forward-fill missing NAVs. | Forward-filling creates a fake 0% day for the fund against a real move in the index, which inflates tracking error. Weekend NAVs create days the benchmark doesn't have. On the first run, 10 TRI days have no NAV for any scheme: Muhurat sessions (12-Nov-2023, 01-Nov-2024, 21-Oct-2025), Saturday DR/special sessions (20-Jan-2024, 02-Mar-2024, 18-May-2024), Budget-day sessions (01-Feb-2025, 01-Feb-2026), and two with an **unverified cause** (28-Sep-2023, 29-Sep-2025). Listed in `data/quality/calendar_mismatch.csv`. |
| D-015 | 2026-09-25 | Downloads with `_PR_` in the name (price return: Open/High/Low/Close) are **rejected** by the parser. Only `_TR_` files are used. The yearly chunks are combined, an overlapping date must carry an identical value, and a calendar gap of more than 7 days stops the pipeline. | Accept the price index; merge chunks by hand in Excel. | The first download was the price index, which excludes dividends. Merging by hand invites silent errors. |
| D-010 (resolved) | 2026-09-25 | Benchmark-weight proxy = **the index fund with the lowest annualised tracking error vs the TRI** over Sep-2024 to Aug-2026 (Direct plan, D-014 calendar), chosen in code by `benchmark_proxy_selection.csv`. First run: Bandhan Nifty 100 Index Fund. Its portfolio disclosures are now required for all 12 holdings months. | Choose by AUM or by the brand of the fund being studied. | Tracking error is a direct measure of how closely the fund's holdings replicate the index, which is exactly what a weight proxy needs. Ranked by code, so it isn't an arbitrary choice. |
| D-016 | 2026-09-25 | Holding weight = **market value ÷ the file's GRAND TOTAL / Total Net Assets**. The reported `% to NAV` is used only as a cross-check (flag if they differ by more than 0.02%). | Use the reported % column. | Units differ by AMC (HDFC and SBI report percent; Bandhan and ICICI report fractions), and holdings below 0.01% are shown as `$` or `^` instead of a number. Market value is always numeric. A grand-total unit check stops the parser if the units are misread. |
| D-017 | 2026-09-25 | A **holding** is a row with a numeric quantity and market value. Rows are classified **by the section they sit in** (equity / non-equity / derivative), never by ISIN prefix. TREPS, cash and net-current-asset lines have no quantity and aren't itemised. `excluded_non_equity_weight = 1 − Σ equity weight`. Each fund-month's Σ equity market value is **reconciled to the file's own equity total**. | Classify by ISIN prefix; itemise every cash line. | Commercial paper (INE929O14…) and preference shares (INE494B04…) have INE ISINs but aren't equity. Reconciling to the file's own total proves no holding was dropped or double-counted: the Aug-2026 gap was 0.00 lakh in all 5 files. |
| D-018 | 2026-09-25 | The portfolio month is read **from inside the file** ("as on" date). A `YYYY-MM__` filename prefix is optional, but if present it must match or the pipeline stops. The download checklist marks a month present only when it has been parsed. | Rely on filenames. | The ICICI file name has no date at all, and AMC links are sometimes mislabelled. |
| D-019 | 2026-09-25 | ICICI: futures are taken from the **in-sheet** "Details of Stock Future / Index Future" table. The `Derivative` annexure sheet is skipped. | Parse the annexure. | In the Aug-2026 file the annexure labels these positions with scheme code `FOCUS` and has a stale "as on March 31, 2026" line. The in-sheet table is scheme-specific and signed. Logged as a source inconsistency. |
| D-020 | 2026-09-25 | **Decided by the user:** active share (main result) = equity weights **plus net stock-futures exposure added to the underlying stock's ISIN**, renormalised over that total. **Robustness:** the brief's original definition (derivatives excluded) is reported alongside. Futures are parsed with sign and mapped to the underlying by company name (8/8 on Aug-2026, verified by hand). Index futures, if any appear, are handled separately in P4. | Exclude derivatives as the brief states. | A long stock future is economically the same as owning the stock. Leaving it out understates the fund's real position (e.g. SBI Kotak +0.76% of NAV in Aug-2026) and inflates active share. This deviates from the brief, so the brief's version is kept as a robustness check. |
| D-021 | 2026-09-25 | Every fund is measured against the **Nifty 100 TRI** (and Nifty 100 index-fund weights), even where the fund states another benchmark. Stated benchmarks are recorded per fund-month (Aug-2026: SBI and Bandhan LC = BSE 100 TRI; ICICI = Nifty 100 TRI; HDFC's benchmark isn't in the file text). | Use each fund's own benchmark. | The study asks about closet indexing *within the SEBI large-cap category*, which is defined by the top-100 stocks by market cap. One common yardstick makes funds comparable. **Limitation:** active share against a fund's own BSE 100 benchmark would differ slightly. |
| D-022 | 2026-09-25 | **P1 bug fix.** NAVAll leaves Plan/Option **blank** for some live schemes (Motilal Oswal Large Cap Fund, all 4 plans). A blank plan is now resolved from the window-start history snapshot's NAV Name ("Motilal Oswal Large Cap Direct Plan Growth"). It's never guessed without a source, and anything left unresolved is written to `data/quality/universe_unresolved_plans.csv`. Survivorship now compares **all** Large Cap plan codes, whatever the option. Universe: 37 → **38 funds (35 active, 3 index)**. | Keep requiring an explicit plan; hand-add Motilal. | The P1 filter dropped Motilal **silently**, which breaks the no-silent-drop rule. Found only because the fund appeared in AMFI's TER export. The unresolved rows on the first run are 9 legacy plans (Edelweiss Plan B/C; ICICI 108467 and 4 PGIM codes with last NAV in 2019–20), none of them Direct/Regular Growth. |
| D-023 | 2026-09-25 | AMFI's TER export splits the Large Cap category across **two spellings** ("Equity Scheme" / "Equity Schemes"), and one "All" download returns only one of them (Aug-2026 export: 10 funds; Jul-2026 export: 25; together all 34 of the original universe plus Motilal). TER must be downloaded **for both spellings, every month**. The TER parser keys on the **NSDL scheme code** (whitespace-normalised) because names vary within a code. | Trust a single "All" download. | Same category-spelling defect as NAVAll (D-002). A single download silently loses about 70% or 30% of the funds depending on the month. |
